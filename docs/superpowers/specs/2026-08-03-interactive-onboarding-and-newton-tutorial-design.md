# คู่มือแบบโต้ตอบสำหรับผู้ใช้ใหม่และแล็บ Newton

วันที่: 3 สิงหาคม 2569

สถานะ: อนุมัติแล้ว

## เป้าหมาย

เพิ่มคู่มือการใช้งานที่ผู้ใช้กดและทดลองตามได้จริง โดยแยกเป็นคู่มือเริ่มต้นตามบทบาทและคู่มือเฉพาะแล็บ ผู้ใช้ต้องเข้าใจขั้นตอนสำคัญได้ภายในเวลาสั้น ๆ และสามารถข้ามหรือเปิดดูใหม่ภายหลังได้

ขอบเขตรอบแรกประกอบด้วย:

- คู่มือเริ่มต้นสำหรับนักเรียนหลังเข้าสู่ระบบครั้งแรก
- คู่มือเริ่มต้นสำหรับคุณครูหลังเข้าสู่ระบบครั้งแรก
- คู่มือเฉพาะ `Newton's Law of Cooling` ในหน้าการจำลอง
- การบันทึกสถานะข้ามอุปกรณ์และการเปิดคู่มือซ้ำจากเมนูตั้งค่า

## สิ่งที่ไม่อยู่ในขอบเขต

- ยังไม่เพิ่มคู่มือเฉพาะให้แล็บอื่น
- ไม่บังคับสร้างชั้นเรียน ส่งงาน หรือบันทึกผลการทดลอง
- ไม่เปลี่ยนค่าการทดลองหรือกดปุ่มแทนผู้ใช้
- ไม่เพิ่มไลบรารี Tutorial ภายนอกและไม่เปลี่ยนรูปแบบหน้าหลักของ SciSiam

## การเริ่มคู่มือหลังลงทะเบียน

หน้าลงทะเบียนยังเน้นการสร้างบัญชีและยืนยันอีเมลโดยไม่มีหน้าต่าง Tutorial มาขวาง เมื่อผู้ใช้เข้าสู่ระบบสำเร็จเป็นครั้งแรก ระบบจะพาไปยังหน้าหลักตามบทบาทและแสดงคำเชิญสั้น ๆ พร้อมปุ่ม `เริ่มคู่มือ` และ `ข้ามก่อน`

- นักเรียนเริ่มที่ `/labs`
- คุณครูเริ่มที่ `/dashboard`
- การข้ามจะหยุดการแสดงอัตโนมัติ แต่ยังเปิดใหม่ได้จากเมนูตั้งค่า
- คู่มือทั่วไปมีไม่เกิน 6 ขั้นและควรจบได้ภายในประมาณ 1 นาที

## คู่มือเริ่มต้นสำหรับนักเรียน

1. แนะนำหน้ารวมแล็บและสิ่งที่ผู้เรียนทำได้
2. ชี้พื้นที่ค้นหาและตัวกรองเพื่อหาแล็บที่ต้องการ
3. ชี้ปุ่มเข้าสู่แล็บ โดยไม่บังคับเปิดแล็บใดแล็บหนึ่ง
4. แนะนำเมนูชั้นเรียนสำหรับเข้าห้องและดูงานที่ได้รับ
5. แนะนำการแจ้งเตือนสำหรับงานและข่าวสารสำคัญ
6. แนะนำเมนูโปรไฟล์ซึ่งใช้เข้าหน้าโปรไฟล์และการตั้งค่า

## คู่มือเริ่มต้นสำหรับคุณครู

1. แนะนำแดชบอร์ดและภาพรวมการสอน
2. ชี้ส่วนชั้นเรียนและทางเข้าสำหรับสร้างหรือจัดการห้อง
3. แนะนำพื้นที่งานทดลองและการตรวจผลงาน โดยไม่บังคับสร้างข้อมูล
4. แนะนำการแจ้งเตือนเกี่ยวกับชั้นเรียนและงานที่ส่ง
5. แนะนำหน้าโปรไฟล์และข้อมูลบัญชี
6. แนะนำเมนูตั้งค่าและทางเปิด Tutorial ซ้ำ

ถ้าบัญชียังไม่มีชั้นเรียนหรือผลงาน ระบบจะอธิบายตำแหน่งทางเข้าเท่านั้นและไม่ใช้ข้อมูลตัวอย่างปลอม

## คู่มือแล็บ Newton

คู่มือนี้แสดงคำเชิญเมื่อผู้ใช้เข้าหน้า `/labs/newtons-cooling/simulation` ครั้งแรก และแยกจากคู่มือเริ่มต้นทั่วไปโดยสมบูรณ์ มีทั้งหมด 7 ขั้น:

1. อธิบายเป้าหมายว่าเป็นการสังเกตการเย็นตัวของวัตถุเมื่อเทียบกับสิ่งแวดล้อม
2. ให้ผู้ใช้ปรับอุณหภูมิเริ่มต้นของตัวอย่างจริง
3. ให้ผู้ใช้ปรับอุณหภูมิสิ่งแวดล้อมจริง
4. รอให้ผู้ใช้กด `เริ่มทดลอง` และให้การจำลองเริ่มทำงานจริง
5. รอให้ผู้ใช้กด `หยุดชั่วคราว` และให้การจำลองหยุดจริง
6. รอให้ผู้ใช้เปิด `ผลการทดลอง`
7. ชี้ตำแหน่ง `บันทึกผล` พร้อมอธิบายว่าใช้เก็บผลภายหลัง แต่จบคู่มือได้โดยไม่ต้องบันทึก

ขั้นที่ต้องลงมือทำจะไม่มีปุ่มถัดไปจนกว่าระบบตรวจพบการกระทำจริง การย้อนกลับไม่ย้อนค่าหรือสถานะของการทดลอง และขั้นที่เคยทำสำเร็จแล้วยังคงถือว่าสำเร็จ

## รูปแบบหน้าตาและข้อความ

- ใช้ระบบสี ตัวอักษร ปุ่ม และระยะห่างเดิมของ SciSiam
- ไฮไลต์เป้าหมายครั้งละหนึ่งจุดและทำให้เป้าหมายนั้นยังกดหรือใช้คีย์บอร์ดได้
- กล่องคำแนะนำแสดงชื่อสั้น คำสั่งหนึ่งอย่าง และลำดับ เช่น `3 จาก 7`
- ขั้นอธิบายใช้ปุ่ม `ถัดไป` ส่วนขั้นลงมือทำใช้ข้อความ `ลองทำที่จุดที่ไฮไลต์`
- มีปุ่มย้อนกลับ ข้าม และปิด โดยไม่วางทับปุ่มหลักของหน้า
- ใช้ภาษาไทยสั้น ตรง และหลีกเลี่ยงคำศัพท์เทคนิคที่ผู้เรียนไม่จำเป็นต้องรู้

## โครงสร้างระบบ

ต่อยอด `FirstLoginTour` และระบบเปิด Tutorial เดิมให้รองรับคำจำกัดความของคู่มือหลายชุด โดยแยกข้อมูลขั้นตอนออกจากตัวแสดงผลกลาง ไม่เพิ่ม dependency ใหม่

แต่ละขั้นมีข้อมูลหลักดังนี้:

- รหัสขั้นและรหัสคู่มือ
- ตัวเลือกเป้าหมายบนหน้าและตำแหน่งกล่องคำแนะนำ
- ชื่อและคำอธิบายภาษาไทย
- ประเภท `อธิบาย` หรือ `ลงมือทำ`
- รหัสเหตุการณ์ที่ต้องรอสำหรับขั้นลงมือทำ

คู่มือทั่วไปของนักเรียน คู่มือทั่วไปของคุณครู และคู่มือ Newton ใช้ตัวแสดงผลเดียวกัน แต่มีชุดขั้นตอนและเงื่อนไขเริ่มต้นแยกกัน จึงสามารถเพิ่มแล็บอื่นในอนาคตโดยไม่คัดลอกระบบแสดงผล

## การตรวจการกระทำจริง

ระบบไม่อาศัยข้อความบนปุ่มและไม่สร้างการคลิกจำลอง ส่วนควบคุมที่เกี่ยวข้องจะรายงานเหตุการณ์เชิงความหมายพร้อมขอบเขตของแล็บ เช่น:

- ค่าอุณหภูมิเริ่มต้นเปลี่ยนเป็นค่าที่ถูกต้องและต่างจากค่าเมื่อเริ่มขั้น
- ค่าอุณหภูมิสิ่งแวดล้อมเปลี่ยนเป็นค่าที่ถูกต้องและต่างจากค่าเมื่อเริ่มขั้น
- สถานะการจำลองเปลี่ยนเป็นกำลังทำงาน
- สถานะการจำลองเปลี่ยนเป็นหยุดชั่วคราว
- แผงผลการทดลองเปิดสำเร็จ

เหตุการณ์ต้องตรงทั้งรหัสคู่มือและรหัสแล็บเพื่อไม่ให้การกดส่วนอื่นทำให้ขั้นผ่านโดยไม่ตั้งใจ รองรับทั้งเมาส์ สัมผัส และคีย์บอร์ด

## สถานะและการบันทึก

เพิ่มตาราง `user_tutorial_progress` ใน Supabase โดยใช้ `(user_id, tutorial_id)` เป็นคีย์ร่วม และเก็บเฉพาะสถานะ `completed` หรือ `skipped` พร้อมเวลาที่อัปเดต เปิด RLS ให้ผู้ใช้เห็นและแก้ไขได้เฉพาะรายการของตนเอง

ใช้รหัสคู่มือแบบมีเวอร์ชัน เช่น:

- `general-student-v2`
- `general-teacher-v2`
- `newtons-cooling-v1`

`profiles.onboarding_completed` ยังคงอยู่เพื่อรักษาความเข้ากันได้กับระบบเดิม แต่ตารางใหม่เป็นแหล่งข้อมูลหลักสำหรับคู่มือแบบมีเวอร์ชัน เมื่อจบหรือข้ามคู่มือทั่วไป ระบบจะอัปเดตทั้งสองตำแหน่ง ผู้ใช้เดิมที่มี `onboarding_completed = true` จะไม่ถูกบังคับให้เริ่มคู่มือทั่วไปใหม่

ตอนเพิ่มตาราง ระบบจะสร้างสถานะสำเร็จให้ผู้ใช้เดิมตามบทบาทปัจจุบัน เช่น นักเรียนได้ `general-student-v2` และคุณครูได้ `general-teacher-v2` จึงไม่รบกวนผู้ใช้เดิม ขณะเดียวกันถ้านักเรียนได้รับอนุมัติเป็นคุณครูภายหลัง คู่มือคุณครูยังแสดงได้หนึ่งครั้งเพราะเป็นคนละรหัสคู่มือ

การเปิดซ้ำจากเมนูตั้งค่าจะไม่ลบสถานะที่เคยจบ ผู้ใช้สามารถเริ่มใหม่ได้ทันทีโดยไม่ทำให้ Tutorial กลับมาแสดงอัตโนมัติในครั้งถัดไป ระหว่างที่กำลังทำคู่มือ ตำแหน่งขั้นปัจจุบันเก็บไว้เฉพาะเซสชันเพื่อให้การเปลี่ยนเส้นทางหรือรีเฟรชไม่เริ่มใหม่ทันที

สถานะ Tutorial ไม่มีคะแนน ค่าการทดลอง หรือเนื้อหาส่วนตัวของผู้ใช้ หากบันทึก Supabase ไม่สำเร็จ คู่มือยังปิดได้ ระบบเก็บรายการรอซิงก์แยกตามผู้ใช้และลองบันทึกอีกครั้งเมื่อเชื่อมต่อได้

## การเปิดคู่มือซ้ำ

เมนูตั้งค่าแสดงทางเลือกที่ชัดเจนตามบริบท:

- `คู่มือเริ่มต้นสำหรับนักเรียน` หรือ `คู่มือเริ่มต้นสำหรับคุณครู`
- `คู่มือแล็บ Newton`

การเลือกคู่มือจะพาไปยังหน้าเริ่มต้นที่ถูกต้องแล้วเปิดคำเชิญ Tutorial ไม่เปิดหน้าต่างหลายชุดพร้อมกัน และถ้ามีคู่มือหนึ่งกำลังทำงานต้องปิดหรือจบชุดนั้นก่อน

## การรองรับมือถือและการเข้าถึง

- รองรับหน้าจอมือถือ 320, 375, 390 และ 414 พิกเซล รวมถึงแท็บเล็ตและเดสก์ท็อป
- กล่องคำแนะนำสลับตำแหน่งอัตโนมัติและไม่ล้นขอบจอ
- เลื่อนไปหาเป้าหมายก่อนแสดงขั้น โดยไม่ใช้การเคลื่อนไหวมากเมื่อผู้ใช้เปิดลดการเคลื่อนไหว
- ประกาศชื่อขั้นและคำสั่งให้โปรแกรมอ่านหน้าจอรับรู้
- ใช้โครงสร้าง Tutorial แบบไม่ล็อกโฟกัส เพื่อให้ผู้ใช้เข้าถึงเป้าหมายที่ไฮไลต์ได้
- รองรับ Tab, Enter, Space และ Escape พร้อม focus ที่มองเห็นได้
- ปุ่มและพื้นที่สัมผัสมีขนาดเหมาะกับมือถือและไม่ถูกแถบนำทางหรือปุ่ม AI บัง

## การจัดการข้อผิดพลาด

- รอเป้าหมายที่กำลังโหลดเป็นช่วงเวลาสั้น ๆ ก่อนแสดงข้อผิดพลาด
- ถ้าหาเป้าหมายไม่พบ ให้แสดง `ลองใหม่` และ `ข้ามขั้นนี้` โดยไม่ปล่อยพื้นหลังมืดค้าง
- ถ้าหน้าปัจจุบันไม่ตรงกับคู่มือ ให้พาไปเส้นทางเริ่มต้นที่กำหนดไว้
- ถ้าสถานะบทบาทไม่ตรง ให้ยกเลิกคู่มือชุดนั้นและไม่แสดงเนื้อหาของอีกบทบาท
- ถ้าการควบคุมทดลองยังใช้ไม่ได้ ให้แสดงเหตุผลจากหน้าการทดลองเดิมและรอจนกว่าผู้ใช้แก้ค่าได้
- การปิด ข้าม เปลี่ยนหน้า หรือออกจากระบบต้องล้างตัวฟังเหตุการณ์และการไฮไลต์ทั้งหมด

## ความปลอดภัยและความเป็นส่วนตัว

- ใช้ Supabase Auth เป็นตัวระบุผู้ใช้และบังคับ RLS ในฐานข้อมูล
- ไม่เชื่อบทบาทจาก localStorage เพื่อเลือกสิทธิ์หรือข้อมูลที่เข้าถึงได้
- ไม่เก็บค่าการทดลอง คำตอบ หรือข้อมูลชั้นเรียนไว้ในตาราง Tutorial
- การเปิด Tutorial ไม่เรียกการบันทึกผล ส่งงาน สร้างชั้นเรียน หรือการกระทำที่เปลี่ยนข้อมูลแทนผู้ใช้

## ไฟล์และส่วนระบบที่คาดว่าอยู่ในขอบเขต

- ระบบแสดงผล `src/components/FirstLoginTour.tsx` และ `src/components/GlobalClientOverlays.tsx`
- ตัวช่วย Tutorial ใน `src/lib/onboarding-tour.ts` และไฟล์คำจำกัดความขั้นตอนใหม่
- เมนูเปิดซ้ำใน `src/components/SettingsModal.tsx`
- จุดเชื่อมเหตุการณ์ใน `src/components/labs/simulation/SharedSimulationShell.tsx`
- ตัวควบคุม Newton ใน `src/components/labs/simulation/NewtonsCoolingSimulation.tsx`
- migration ใหม่และ `src/lib/supabase/database.types.ts`
- regression tests ของ Tutorial และการจำลองที่เกี่ยวข้อง

ตำแหน่งไฟล์ใหม่และรายละเอียดการแยก component จะยืนยันอีกครั้งในแผนดำเนินงาน ไม่มีการลบไฟล์และไม่มีการเพิ่ม dependency

## การทดสอบและเกณฑ์ผ่าน

- นักเรียนใหม่เห็นเฉพาะคู่มือของนักเรียน และคุณครูใหม่เห็นเฉพาะคู่มือของคุณครู
- ผู้ใช้เดิมที่จบ onboarding แล้วไม่ถูกบังคับให้ดูคู่มือทั่วไปใหม่
- ขั้น Newton ไม่ผ่านจากการกด `ถัดไป` หรือคลิกส่วนอื่น แต่ผ่านเมื่อสถานะจริงตรงตามเงื่อนไข
- การปรับค่าด้วยเมาส์ สัมผัส และคีย์บอร์ดทำให้ขั้นผ่านได้เหมือนกัน
- การจบหรือข้ามถูกจำข้ามอุปกรณ์ และการเปิดซ้ำไม่รีเซ็ตสถานะถาวร
- เป้าหมายที่หายหรือโหลดช้าไม่ทำให้หน้าค้าง และผู้ใช้สามารถลองใหม่หรือข้ามได้
- การย้อนกลับไม่เปลี่ยนค่าหรือสถานะการทดลองย้อนหลัง
- ตรวจหน้า `/login`, `/labs`, `/dashboard`, เมนูตั้งค่า และ `/labs/newtons-cooling/simulation`
- ตรวจอย่างน้อยที่ความกว้าง 320, 375, 390, 414 พิกเซล แท็บเล็ต และเดสก์ท็อป
- ตรวจคอนโซล การล้นหน้าจอ การใช้งานคีย์บอร์ด และโหมดลดการเคลื่อนไหว
- รัน regression tests, lint และ production build

## การขยายในอนาคต

เมื่อ Newton ผ่านการใช้งานจริงแล้ว สามารถเพิ่มคู่มือแล็บอื่นด้วยชุดขั้นตอนและรหัสเหตุการณ์ของแล็บนั้น โดยใช้ตัวแสดงผล ตารางสถานะ และเมนูเปิดซ้ำชุดเดิม ไม่ต้องสร้างระบบ Tutorial ใหม่
